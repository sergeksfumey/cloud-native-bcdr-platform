# DR Test Operational Runbook

## Monthly Automated DR Test

Schedule: 1st of each month, 2 AM UTC
Pipeline: dr-test-pipeline.yml
Triggered by: Azure DevOps schedule (automatic, no manual trigger required)

## Pre-Test Checklist (day before)

1. Confirm ASR replication health: all VMs in Normal state
   az site-recovery replicated-item list --vault-name rsv-asr-prod
2. Confirm test-failover-vnet exists and has no unexpected peerings
3. Confirm pipeline variable group bcdr-prod-vars is current
4. Notify operations team of scheduled DR test window

## During Test

Pipeline executes automatically. Monitor in Azure DevOps:
- Stage 1: PreTestValidation (5 min)
- Stage 2: TestFailoverExecution (20-30 min)
- Stage 3: RecoveryValidation (10 min)
- Stage 4: TestCleanup (5 min)
- Stage 5: ReportResults (5 min)

Total expected duration: 45-60 minutes

## If Test Fails

Stage 1 failure (replication health):
- Investigate unhealthy VMs in ASR portal
- Check ASR Mobility Service status on affected VMs
- Do not proceed with test until replication health is Normal
- Reschedule test after resolution

Stage 2 failure (test failover execution):
- Check ASR job logs in Recovery Services vault
- Common causes: insufficient quota in Central US, network mapping issue
- CleanUp stage runs automatically (always condition)
- Investigate before rescheduling

Stage 3 failure (validation):
- Application health check failed: investigate recovered VM startup logs
- RTO exceeded: review recovery plan group timing, add wait steps if needed
- RPO exceeded: check ASR replication lag before test execution
- CleanUp stage runs automatically

Stage 4 (cleanup) always runs -- confirm test environment cleaned up even on failure:
  az site-recovery replication-recovery-plan show --name order-processing-recovery
  Check: no test failover state remaining

## DR Test Report Distribution

Report generated by Stage 5, published as pipeline artifact.
Download from Azure DevOps: Pipelines > DR Test > Latest run > Artifacts > dr-test-report

Distribute to:
- Governance team: compliance evidence for regulatory audit
- CISO/CTO: DR readiness executive summary
- Operations team: operational RTO/RPO performance data

Store in: SharePoint > DR Governance > Monthly Test Reports > YYYY-MM

## Annual DR Test Review

At end of each year:
1. Review 12-month DR test result trend
2. Identify any RTO/RPO breaches and root causes
3. Update recovery plans based on infrastructure changes
4. Update target RTO/RPO if workload criticality has changed
5. Present DR readiness summary to executive team
